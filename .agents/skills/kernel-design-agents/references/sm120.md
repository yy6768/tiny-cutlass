# SM120：Blackwell RTX 端侧迁移

这里的 SM120 指 compute capability 12.0。上游 KDA 的 KernelWiki / NCU 默认面向
SM100/B200；它们的 Blackwell 标签不能直接决定本页的实现。

## 已核对的实现边界

当前 CUTLASS 4.5.2 的
[example 79](../../../../3rdparty/cutlass/examples/79_blackwell_geforce_gemm/)
明确针对 SM120 / GeForce RTX 50 系列，并使用 warp 级 block-scaled `mma.sync`。
其示例采用 TMA 和 warp-specialized schedule；TMA load **不支持 multicast**，
cluster shape 必须是 `1×1×1`，且不支持示例所称的 dynamic datatypes。
所以不能把 SM120 简化成“只有旧 MMA、没有 TMA”，也不能照搬 SM100 的 2-SM 设计。

对应实现入口：

- [MMA 指令封装](../../../../3rdparty/cutlass/include/cute/arch/mma_sm120.hpp)。
- [SM120 collective builder](../../../../3rdparty/cutlass/include/cutlass/gemm/collective/builders/sm120_mma_builder.inl)。
- [NVFP4 输入 / BF16 输出示例](../../../../3rdparty/cutlass/examples/79_blackwell_geforce_gemm/79a_blackwell_geforce_nvfp4_bf16_gemm.cu)。
- [示例编译目标](../../../../3rdparty/cutlass/examples/79_blackwell_geforce_gemm/CMakeLists.txt)。

SM120 路线不使用 Hopper WGMMA 或 SM100 的 `tcgen05` / TMEM accumulator。
低精度支持按具体 MMA 指令、scale 格式和库实例逐项核对。
依据：[PTX warp MMA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#warp-level-matrix-instructions-mma)、
[PTX tcgen05](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#tensorcore-5th-generation-instructions)。

## 工具链与资源

本地 CUTLASS CMake 为 120/120a 要求 CUDA ≥ 12.8，为 120f 要求 ≥ 12.9。
example 79 的条件含 `120a|120f|121a`；本任务选择 SM120 时只取适用的 120a/120f。
`120f` 的适用性依赖指令与版本，不能机械替换所有 `120a`。
本机 CUDA 12.9 的存在只是工具链条件之一；当前根 CMake 仍会拒绝 SM120。

优先把普通 FP16/BF16 基线与特性目标的低精度实现分成显式 policy。
确认架构条件宏和 SASS，防止示例在不支持设备上直接跳过却被当作测试通过。

per-block shared-memory 预算可对照当前 CUTLASS
[arch 常量](../../../../3rdparty/cutlass/include/cutlass/arch/arch.h) 的 101376 bytes（99 KiB）。
per-SM 资源、实际可用 shared memory、SM 数、L2、显存和带宽都从设备查询，
不要把 [Blackwell 调优指南](https://docs.nvidia.com/cuda/blackwell-tuning-guide/index.html)
中 B200 的 228 KiB/SM、HBM 或互连参数复制到 RTX。

## 分阶段实现

1. **同语义基线**：在 SM120 目标上编译 FP16/BF16 TensorOp policy，运行与 SM89 相同的
   reference/shape 集。目标不可用时先完成源码和编译审查，明确运行待验证。
2. **重新调 tile/stage**：以实际 register/shared-memory 和 small-batch 并行度为依据。
   对 attention 保留精确 mask、softmax 和输出语义，不照搬 B200 flash-attention tile。
3. **融合**：MLP epilogue、residual、norm modulation、layout 变换按真实中间张量成本排序。
   每次记录融合省下的读写与增加的 register / synchronization。
4. **独立低精度候选**：按 example 79 核对 NVFP4/MX 格式的数据编码、block size、scale
   dtype/layout、global scale、alignment 和 tail。FP8、MXFP8、NVFP4 不共享一个含糊的
   “量化参数”契约。权重离线打包与 activation 在线量化分别计时。
5. **运行验收**：先 operator parity，再 denoiser 单步，最后固定 prompt/seed/scheduler
   的完整采样。检查不同 timestep 的误差与异常值；成本包括量化、重排和 workspace。

## 候选与淘汰条件

| 候选 | 预期解决的问题 | 何时淘汰 |
|---|---|---|
| FP16/BF16 GEMM epilogue fusion | launch 和中间张量流量 | register/spill 导致整体更慢 |
| TMA warp-specialized schedule | 搬运与计算重叠 | 小 shape 的设置/同步成本超过收益 |
| NVFP4 GEMM | 大线性层的算力、带宽或显存占用 | 含量化/重排的总时延未改善，或模型质量不达标 |
| attention tile / split 调整 | 长序列资源压力或小 grid | 合并成本、精度或高频 shape 退化 |

不要把量化与原 FP16 运算的差异藏在放宽的 kernel 容差中：先对齐相同量化格式的数学
reference，另设相对原模型的质量验收。具体阈值由任务契约给出。

达到“支持 SM120”需要目标设备的 parity、普通运行 benchmark 和实际 dispatch 记录。
上游示例存在、编译器识别架构或头文件含 `Sm120` 都不能单独满足此条件。
