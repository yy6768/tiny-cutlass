# SM89：当前 Ada 端侧路线

目标是先把当前 RTX 4070 Laptop GPU 上的 Diffusion 热点做成可复现的实验。
GPU 名称来自安装时系统枚举；运行测试时仍以 CUDA runtime 返回的设备为准。

## 能力与资源预算

Ada 的并发 warp 上限为每 SM 48，register file 为 64K 个 32-bit register，
shared memory 为每 SM 100 KiB、每 block 最多 99 KiB。超过默认 shared-memory 分配限制
时需检查动态 shared memory opt-in；tile 和 pipeline stage 都要纳入预算。
这些上限不是理想 occupancy，也不能代替目标 kernel 的实际资源统计。
依据：[Ada occupancy / memory](https://docs.nvidia.com/cuda/ada-tuning-guide/index.html)。

以 warp `mma.sync` TensorOp、`cp.async` 多 stage 搬运和 epilogue fusion 为主线。
SM89 不具有 Hopper 的 TMA/WGMMA 路径。FP8 可作为独立候选；支持 FP8 不表示已有
任意 shape/layout 的高效实现，也不意味着量化后的模型质量自然通过。
依据：[Ada FP8 示例](../../../../3rdparty/cutlass/examples/58_ada_fp8_gemm/ada_fp8_gemm.cu)、
[PTX ISA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html)。

不要用 RTX 4090 / AD102 的全芯片缓存、带宽、SM 数或桌面功耗预算替代本机参数。
架构上限与产品配置必须分开记录。

## 源码入口

| 目的 | 当前仓库入口 | 先核对什么 |
|---|---|---|
| FP16/BF16 attention | [flash-attention](../../../../csrc/flash-attention/) 和 [CUTLASS example 41](../../../../3rdparty/cutlass/examples/41_fused_multi_head_attention/) | mask、head dimension、softmax、tail；先读 family AGENTS |
| FP8 GEMM | [example 58](../../../../3rdparty/cutlass/examples/58_ada_fp8_gemm/) | element、alignment、accumulator、scaling |
| 卷积与融合 | [conv-fused](../../../../csrc/conv-fused/) | 当前是哪些卷积 family、布局和融合边界 |
| MLP / norm / layout | [swin](../../../../csrc/swin/) | 复用 policy/harness 的方式；不假定 Swin 语义等于 DiT |

CUTLASS 提供的 `Sm80` MMA 组件可以被 SM89 policy 使用；这表示指令组件的要求，
不等于 launcher 可以绕过设备检查。目标实例与编译配置仍要明确选择 SM89。

## 实验顺序

1. 从 [Diffusion trace](diffusion.md) 得到真实 M/N/K、attention 长度或卷积尺寸，建立
   FP16/BF16 reference。为 fused op 同时保留 unfused reference。
2. 对 GEMM/MLP，先测 bias/activation/residual 融合是否减少实际内存流量和 launch，
   再调 tile/stage。小 M 时大 tile 可能带来尾部浪费。
3. 对 attention，检查 softmax/reduction 的代价以及 query/head/batch 提供的并行度。
   只有 grid 太小且测量支持时才试 split；把 split workspace 和合并成本计入总时间。
4. 对 convolution，先比较 cuDNN 和现有 implicit-GEMM。保留 layout 转换时间；不能把
   1x1 的连续融合策略直接套到任意 3x3/group convolution。
5. 每个候选观察 ptxas register/shared-memory、spill、实际 occupancy、DRAM/L2 流量
   和 stall；判断 tile/stage 改变为何有效。
6. FP8 放在稳定数值基线之后，测 quantize/scale/reformat 的完整成本，再做 denoiser
   单步与完整采样质量验证。

以上是待测假设，不预设收益。笔记本上采用固定供电和可重复热状态，交替重复 baseline /
candidate；用未挂 profiler 的结果判断性能。

## 验收

- 所有契约内 shape、mask、tail、dtype 通过；记录 max abs / relative error 等，不能只看均值。
- 多次普通运行的延迟改进超过噪声，且高频 shape 不退化；融合成本完整计入。
- 记录 GPU 名称、频率/温度/功耗状态、软件版本、编译目标和实际 kernel 名。
- 单步/端到端改进按 [Diffusion 验收](diffusion.md) 复核，NCU 用来解释结果。
