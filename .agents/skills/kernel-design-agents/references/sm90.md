# SM90：Hopper 路线

SM90 是用户需要的独立架构目标。本次仅建立设计与验证路径；根 CMake 尚未开放它。
Hopper 设备上的高吞吐结果不能直接代表 SM89 / SM120 的端侧延迟。

## 能力与源码

Hopper 可使用 TMA、thread block clusters 和 distributed shared memory。
TMA 搬运与计算要通过 barrier/pipeline 建立正确的完成与可见性关系。
架构资源上限包括每 SM 64 warps、228 KiB shared memory、每 block 227 KiB；
实际 kernel 的 stage、register 和 cluster occupancy 仍需单独计算。
依据：[Hopper 调优指南](https://docs.nvidia.com/cuda/hopper-tuning-guide/index.html)。

WGMMA 是 warpgroup 异步 MMA 路线，应采用满足要求的 `sm_90a` 特性目标。
warpgroup 的参与、fence、commit/wait 和 shared-memory buffer 生命周期都属于正确性。
不能把 `__syncthreads()` 当作覆盖所有异步完成条件的替代品。
依据：[PTX WGMMA](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#asynchronous-warpgroup-level-matrix-instructions)、
[CUTLASS example 48](../../../../3rdparty/cutlass/examples/48_hopper_warp_specialized_gemm/)、
[example 49](../../../../3rdparty/cutlass/examples/49_hopper_gemm_with_collective_builder/)。

建议先读 example 49 的 collective builder 和 example 48 的 producer/consumer 分工，
再考虑 [example 57 grouped GEMM](../../../../3rdparty/cutlass/examples/57_hopper_grouped_gemm/)
或 [example 55 mixed dtype](../../../../3rdparty/cutlass/examples/55_hopper_mixed_dtype_gemm/)。
复用公开组件，不把上游示例里的具体类名变成当前仓库新增公共 API。

## 迁移步骤

1. 保持 SM89 已建立的算子描述、reference 数据和数值契约；增加 Hopper 的显式 policy。
   先分清是普通 MMA 的可移植实现，还是 WGMMA 专用实现。
2. 检查所选 builder 的 layout/alignment、tile、dtype 和 epilogue 组合。
   主类型保持 `DefaultXxx<ArchTag, Element..., Shape...>`；实例选择在 launcher 层。
3. 为此 family 单独接入构建检查。验证 CMake / Toolkit 对 `90a` 的处理，确认实际 nvcc
   `-gencode`。只改全局 allowlist 不算完成 Hopper 支持。
4. 先以简单 schedule 建立 parity，再比较 TMA stage、producer/consumer 分工和
   ping-pong/cooperative schedule。资源增加可能抵消搬运收益。
5. Cluster/multicast 仅在有数据复用、目标运行配置允许且 occupancy 合理时尝试。
   查询 cluster 支持与占用；小 batch、MIG 等运行条件要另记。
6. 在 SM90 实机按 build → verify → bench 运行，再做 NCU。异步路径调试可增加
   compute-sanitizer 检查；benchmark 使用正常优化构建，不能混用调试耗时。

## Diffusion 的重点实验

| 算子 | 可检验假设 | 需防止的语义/成本遗漏 |
|---|---|---|
| DiT QKV / MLP GEMM | TMA 和 WGMMA 重叠搬运与计算 | 小 M 供给不足、epilogue 写回和 bias/gate 成本 |
| Self / cross attention | tile 内 online softmax 减少中间矩阵 | 非因果 mask、不同 Q/K 长度、FP32 reduction、tail |
| AdaLN / residual 融合 | 减少连续 pointwise launch 和读写 | norm epsilon、broadcast、调制和残差的先后顺序 |
| FP8 线性层 | 降低带宽或提高 Tensor Core 吞吐 | activation scaling、异常值、完整 denoising 质量 |

## 架构边界与验收

Hopper 不采用 SM100 的 TMEM accumulator / `tcgen05` 编程模型。
`compute_90a` PTX 也不能作为 SM120 的前向兼容交付物。
依据：[Blackwell 兼容性说明](https://docs.nvidia.com/cuda/blackwell-compatibility-guide/index.html)。

验收记录至少区分普通 90 与特性目标 90a、baseline policy 与新 policy、每个 shape 的
parity 和普通运行耗时。只有编译证据时标注“编译通过，SM90 实机验证待完成”；
没有编译证据则仍是设计候选。回归检查原 SM89 路径后，才扩大 family 支持声明。
